# OMaaX 0.4.37 — 公司对话模型接入

## 范围

按《PlantAI-cloud-APP接入指南-第三方LLM.md》复用软件登录，获取 `/api/llm/models` 中首个启用模型，通过 `/api/llm/token` 获取短期代理凭据，再请求 `https://llm.haiguji.com/v1/chat/completions`。

- 设置、首次使用引导和聊天提醒不再要求用户填写对话模型 Key。右键“问一下”也走公司服务。
- 不新增低/中/高推理档位，不新增支付、计费、余额限制或管理员后台功能。
- 不再查询用户私人 DeepSeek 余额。本机对话 token 统计保留，并说明它不是账号总用量或余额。
- 原私人模型配置保留以便回退，不作为公司服务失败的备用通道。
- 图像生成、MCP、知识库、科研、SSH、任务与删除保护业务逻辑保持原样。

## 实现

- 新增 `company_llm.rs` 管理受随机凭据保护的回环 Node 代理。公司用户 token 通过原生凭据存储和子进程私有管道读取，不发送到 UI；第三方 Key 从未进入客户端。
- `resources/scripts/company-llm.mjs` 使用固定转发目的地址，拒绝跨源浏览器请求、错误本机凭据和未知路由；请求体有大小上限，并发有界。
- 每次调用检查当前登录，短期 token 提前刷新，同账号并发刷新合并。401 或明确模型授权失效在收到成功流之前最多刷新重试一次。
- 成功流原样传递正文、工具调用分片和 usage；不重放已经开始的流。取消或退出时中止请求，代理随主程序管道关闭退出。
- DSH 启动配置和设置一起覆盖，防止 SDK 首次调用仍使用旧凭据。显示 OMaaX 通用模型名，隐藏 SDK 私人模型设置/模型选择入口。当前不实现推理档位，采用供应商默认推理行为。
- 当前适配只实现文档的 Chat Completions，不假定存在供应商文件上传/余额接口。默认 SDK 上下文预算 65,536、最大输出 8,192；授权其他上下文更小的模型前需核对兼容性。

## 测试及边界

- 公司代理模拟测试 18 项通过：默认授权模型、凭据隔离、未授权、本机请求保护、续签、错误、限流、流式工具调用和取消等。
- 内置真实 SDK 配合模拟公司服务：正文、工具调用、usage、配置路径 4 项通过。首次测试发现单独修改设置不能覆盖启动时凭据，修复启动配置后通过。
- 真实公司服务：一个既有内测账号，两次短请求；普通回答成功并返回 usage，SSE 工具调用成功并含 usage 和 DONE。没有创建账号、修改授权或执行服务器工具。
- TypeScript 通过；原生 Rust 串行回归 41 项通过、2 项显式忽略。
- UI/保护规则 50 项通过；浏览器模型入口 6、外部工具 7、模型流程/结果 13、登录 17、知识库 18、账号 7、知识库布局 5；服务器管理另有 10 组通过。
- 17 个既有 SSH 与保护插件资源与 0.4.36 发布记录哈希一致。
- 未全面测试所有未来授权供应商、小时级模型长任务或生产知识库；没有修改这些服务。模拟与少量真实请求不等于生产服务长期稳定性保证。
