# OMaaX 0.4.39 更新日志

发布日期：2026-10-20

## 本次更新

- **界面稳定性**：服务端推理档位响应异常时显示不可用状态，避免整个对话页面崩溃；设置中移除“对话服务”入口。
- **三档推理模式**：对话中可选择低、中、高，使用公司提供的模型服务；不需要用户填写 API Key。可用档位遵循服务端授权。
- **普通用户运行分析**：继续使用用户级 Conda，不强制 sudo、Podman 或容器隔离。优先发现已有公共 Conda，并在依赖缓存齐全时离线创建独立环境。
- **计算节点提交**：检测到 Slurm 集群后，将流程输入扫描、校验和计划准备放到计算节点；准备完成后根据用户真实执行指令自动提交分析。普通服务器继续使用本机任务执行方式。
- **关闭软件后继续执行**：输入准备与分析作业独立于桌面连接；记录调度编号和提交状态，避免连接中断后盲目重复提交。
- **异常续跑**：保留已完成步骤、日志和失败输出。恢复校验与文件恢复也放到计算节点，完成后继续提交未完成步骤。
- **修复真实续跑缺陷**：修复 Conda 任务内部绝对链接在快照中被误判为外部链接的问题；新流程采用相对内部链接，继续拒绝真正的外部链接。
- **结果与日志追踪**：流程记录显示输入准备状态；保留结果清单、日志分段和读取位置，便于查看长时间任务。
- **删除提醒保护**：保留对话内的路径、范围、大小提醒及可信界面回执；模型不能自行提交回执。默认保留输入、结果另存，支持回收站恢复。

## 小数据验收

使用独立诊断目录、两条合成蛋白序列和对应 GFF 注释；未对真实研究数据执行删除。

1. **节点放置**：输入预处理在 node17 执行；后续正式“基因组预处理→候选成员检查”通过 Slurm 自动提交并完成。
2. **完整自动提交**：真实 SDK 用户消息 → 可信任务指令 → 模型工具调用 → 原生连接层 → Slurm 输入准备 → 固定流程 → 结果读取，整条链路通过，返回 9 个结果文件。为保证可复现，本轮模型回复使用确定性测试服务；真实公司模型的三档调用另有独立验证。
3. **异常恢复**：在第一步检查点落盘后强制终止测试进程。重新连接后正确识别中断，修复后从第二步完成；第一步日志哈希不变、原始输入哈希不变，失败输出保留在单独的历史目录。
4. **依赖准备**：在无法解析外部 Conda 软件源的集群环境，利用公共缓存成功创建 Python/PyYAML/Pandas 环境，全程未使用 sudo 或 Podman。

## 测试边界

- 上述是小数据工程验收，不代表所有大规模生物学流程或数天连续负载均已验证。
- 故障注入是任务进程强制终止，没有对实际集群断电或重启节点。
- 缓存中没有的依赖仍需要可访问的软件源或预先准备的软件包；没有实现任意离线依赖的跨机器自动搬运。
- Conda 直接运行继承 SSH 账号权限；软件删除提醒不是操作系统级文件隔离。
- 旧任务的执行组件或输入发生变化时，系统可能拒绝直接续跑，以免混用不同版本结果。
