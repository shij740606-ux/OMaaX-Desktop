# 账号隔离部署

0.4.25 不再允许登录账号直接复用未分配的 SSH 系统账号。管理员应先为每个使用者配置独立 Linux UID、独立登录凭据和权限为 0700 的家目录，再建立访问绑定。不要给普通分析账号共享私钥、sudo 权限、宿主容器 socket 或其他用户目录的可写权限。

绑定文件为 `/etc/omaax/accounts/<Linux UID>.json`，文件及所有父目录必须归 root 所有，不允许普通用户写入，也不允许符号链接。客户端在远程命令、目录读取、流程包上传和跨服务器传输前检查绑定；账号不匹配、绑定缺失、无法验证时全部拒绝。模型不能创建或更改绑定。

管理员审查该系统账号已有数据归属后执行（替换示例值）：

```sh
sudo python3 provision-account.py --hub http://192.168.0.175:8090 \
  --user-id LOGIN_SERVICE_USER_UUID --linux-user DEDICATED_LINUX_USER \
  --data-ownership-reviewed
```

脚本位于 `desktop/scripts/provision-account.py`。它只创建尚不存在的绑定文件，不创建系统账号、不改目录权限、不搬迁历史数据、不覆盖旧绑定。服务地址先按 URL origin 规范化，再与登录 UUID 合成绑定身份；不是可变用户名。

账号重新分配由管理员单独处理并先备份绑定与核对数据归属，不提供客户端“一键占用”。共享参考数据库可只读授权，个人输出和凭据不能共享。不同 UID 的 CPU/内存总额仍需由系统 cgroup 或集群队列控制，客户端每账号调度不是跨租户调度器。

Windows 也必须使用独立操作系统账号才能获得操作系统级文件和凭据隔离。同一 Windows 登录身份下的软件账号切换只提供应用级目录隔离，不能抵抗该操作系统用户直接读取本地文件。软件没有通过隐藏目录解决这一限制，也不会自动把历史配置或对话归属给首个登录账号。

本次没有修改生产服务器的系统账号、文件权限、绑定文件或登录服务开关。正式部署仍需管理员完成上述配置及真实登录、禁用账号、切换账号验收。部署前请保留现有可用客户端。
