# 0.4.25 可靠性与账号边界

本次交付为源码提交，包含此前尚未提交的 0.4.23 账号功能、0.4.24 用户体验调整及本次四项完善。没有替换用户已安装程序或更改生产登录服务。

## 行为

1. 固定流程成功完成一步后，在容器输出挂载以外保存完整快照及文件 SHA256。失败、取消或中断的任务可由用户在流程页或分析结果页发起续跑。确认计划、输入、镜像、源码版本及快照均需通过检查；恢复前拒绝仍在运行的容器。此前输出移至独立 attempt 目录保留，不删除。
2. 同一系统账号最多准入 4 个任务，并按 CPU 与内存声明预留；排队不再计入执行超时。跨系统账号的资源公平性仍由系统或集群调度器提供。
3. 原生客户端从当前已鉴权身份生成服务器绑定标识。SSH 执行、SFTP 浏览、流程上传及传输均检查管理员维护的 root 所有绑定文件。管理员配置脚本不覆盖绑定，不迁移历史数据。部署步骤和 Windows 隔离边界见 ACCOUNT-DEPLOYMENT.md。
4. 连续 3 次修复失败暂停新的变更工具，保留查询与取消；只跟踪本对话提交或明确查询的任务，重复轮询同一失败不重复计数。每段 80 次模型步骤或 200,000 已报告 tokens 后拒绝下一次模型步骤，用户明确确认后可重置本段额度。用量缺失时仍有次数上限；数值不是费用报价。用量在响应结算后更新，单次响应可能跨过 token 阈值，不能宣称严格的预付金额上限。

## 边界与资源代价

- 续跑从已完成的步骤边界开始，不恢复某个第三方程序的进程内状态。旧任务无快照时不能追溯恢复；运行环境或源码版本变化需要新计划。
- 快照采用完整复制，要求额外磁盘空间并增加步骤间保存耗时；检查可用空间后才复制，空间不足停止并保留结果。快照、失败输出均不自动清理，之后清理由用户确认。
- 普通对话运行的任意脚本没有固定步骤契约，不提供伪造的通用断点恢复。
- 生产账号服务尚未完成真实登录验收，服务器账号绑定尚未部署。缺失绑定将拒绝业务访问，必须先由管理员按部署说明配置独立系统账号。
- 同一 Windows 用户仍不能获得不同软件账号之间的操作系统级隔离，需要独立 Windows 账号。没有把这一部署前提描述为已由客户端解决。
- 没有运行九类流程的全量样本或数天压力测试；不声称任意失败都可自动修复。

初次新增续跑测试夹具缺少步骤镜像字段，修正后通过；登录竞争测试的模拟时钟移到页面初始化前安装后稳定通过。失败日志保留，不作为通过证据。
