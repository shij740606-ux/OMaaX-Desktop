# OMaaX 0.4.38 验证与发布记录

日期：2026-10-20

## 本次改动

- 普通 SSH 账号使用用户目录内的 Conda/Micromamba 配置环境和执行分析。新任务不再强制依赖 sudo、Podman、Bubblewrap、slirp4netns 或 user namespace。
- 保留旧环境、原始数据、任务记录；升级时重新检查基础环境，不把旧容器的就绪状态当成 Conda 就绪。
- 依赖安装在新的环境目录进行，成功检查后才更新流程配置。失败日志保留，修正方案后可重试。
- 任务缓存使用独立目录，避免移除容器后并发任务共用临时缓存。
- 分析结果保存在独立任务目录，保留日志、取消、执行超时、资源排队、步骤快照校验与失败续跑。固定流程复制输入后执行。
- 每次通过软件文件工具发起删除（包括单个小文件和零字节文件）都只生成待确认请求。在对话中展示路径、文件/目录数量、递归范围及精确字节数；用户点击确认后移入回收站。模型无权调用确认接口。执行前再校验文件快照，范围变化必须重新确认。
- 对话中只展示当前对话关联的删除卡片；服务器管理保留集中查看与取消入口。
- 移除设置中的“对话服务”分类及说明页，默认打开“账号和用量”。公司模型接入不变。

## 边界

- 直接运行继承 SSH 系统账号权限。删除确认约束软件的删除工具，不是操作系统沙箱；任意分析脚本及第三方程序仍有该账号的文件访问能力。不能宣称任意脚本都无法删除或覆盖文件。
- CPU 亲和性和单进程地址空间上限继续有效；这不等同于容器 cgroup 的进程组总内存限制。
- 未对全部九类流程做真实大型生物数据分析，未模拟连续十几小时任务或全部 Linux 发行版。小型质控通过不代表所有生物分析科学结果已验收。
- 本次打包不自动覆盖桌面安装，不改用户配置或对话记录。

安装包哈希、解包资源一致性及未登录入口检查见 `release-verification.json`（打包校验后生成）。
