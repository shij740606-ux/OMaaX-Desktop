# 0.4.24 用户交付检查

日期：2026-10-17。用户授权真实服务器小任务、环境安装及真实语言模型调用。生产账号服务尚未开启鉴权；没有修改其开关、创建真实账号或把历史配置/对话分配给测试账号。

## 实际修复

- 登录页改用“服务地址”和账号使用说明；移除早期升级弹窗、内部组件升级解释与无效连接表单。启动失败日志默认折叠。历史工作文件与不可用步骤使用操作提示。
- 工作空间加载失败不再停留在空白页，提供重新加载。问答账号不显示无权限的分析文件/环境入口；内网模型不再错误提示缺少云端密钥。
- 退出或登录期间忽略此前发起的状态检查结果，避免迟到响应恢复旧界面。错误密码明确提示检查用户名和密码。当前账号可以打开自己的数据目录，跨账号路径仍拒绝。
- 服务器任务使用独立可写容器层；HOME=/tmp、XDG_CACHE_HOME=/tmp/.cache，临时文件使用磁盘空间，取消固定 256 MiB 临时盘上限。真实测试发现部分已有镜像的 /root 无权访问，已通过上述配置修复。
- 允许任务使用隔离的外网连接下载依赖和调用在线服务，禁止主机回环访问。移除仅因禁网而永久阻断 NCBI 等步骤的旧声明。服务本身是否可用、是否需要账号以及许可限制仍需满足实际要求。
- 继续使用非特权 SSH 账号、rootless 容器、cap-drop=ALL、no-new-privileges 和资源限制。仅当前任务输出可写回服务器，原始输入和参考文件只读；不挂载宿主根目录、SSH 凭据或 Docker/Podman 控制接口。
- 环境方案、日志读取、错误修复和重试可由模型执行；固定流程初始计划、受限制删除及已有文件覆盖仍由用户确认。管理员账号不能让模型调用审批工具。

## 实际连接状态与限制

- 175：主机指纹匹配、SSH 验证、SFTP、资源读取、实际任务通过。
- spark：主机指纹匹配、SSH 验证、SFTP、资源读取和跨服务器传输通过；本轮没有在 ARM 服务器执行全套分析软件。
- 176：两次 SSH 握手超时，未发送后续业务任务；不能算通过。
- 生产用户名/密码登录：等待管理员启用服务及准备账号。未绕过强制登录，也未把 `auth_enabled=false` 当作可匿名使用。
- 图像生成、外部应用连接、自定义远程助手及历史数据自动导入在账号模式下仍不可用；已移除误导用户“保存即可使用”的表单，明确显示功能不可用。知识库继续隐藏。
- 独立容器层的依赖变更仅属于该任务，持久复用依赖应通过环境准备工具构建并登记。运行任务可联网，因此不再具备完全离线的网络隔离属性；主机权限和输入只读限制保持。
- 同一操作系统/SSH 用户仍具有其系统账号自身的文件访问能力，应用级账号隔离不等于操作系统级隔离。
