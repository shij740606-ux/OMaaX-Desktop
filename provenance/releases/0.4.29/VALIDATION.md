# 0.4.29 账号与知识库集成验证

日期：2026-10-17。开发分支：feature/cloud-auth-qa。

后续稳定性修复见 [STABILITY-REVIEW.md](STABILITY-REVIEW.md)。下述安装包验证记录属于后续修复前的构建，不能视为最新源码已打包或安装。

## 评估与修复

1. 云端角色为 researcher/guest，旧客户端角色校验不兼容：补充角色解析，默认强制登录，独立知识库授权。
2. 真实服务将引用块规范为 `type=sources, items=[...]`。旧请求字段导致引用保存后消失：已按实际协议修复，原生真实登录、退出、重新登录后验证 DOI 恢复。
3. 问答页面卸载会丢弃正在处理的回答：切换功能时保留组件，继续保存；注销和权限撤销仍卸载页面。
4. 教育科研使用独立系统账号绑定会阻止已批准的共享模式：仅固定科研代理使用共享 SSH 身份，要求 bioflow/docgen，保留分析和文件系统的独立绑定要求。
5. 前端测试仍断言旧知识库入口隐藏，无法发现新入口问题：更新测试为新入口可见，以及仅 bioflow 用户无云问答/科研入口。
6. 中断后构建进程卡在资源复制：停止本任务遗留进程，原生单测以测试专用空资源列表运行；正式发布仍打包完整资源。

## 尚需持续验证的边界

- 已确认的服务端风险：真实测试仍能用 API 文档中的默认管理员凭据登录管理后台。应由服务管理员更换默认密码；本次未修改生产管理员凭据，也未在源码、报告或安装包中记录该密码。
- 热更新期间的长期可用性、长时间并发、200 用户负载未测试；用户授权上限不等于必须创建 200 个账号。
- 知识库回答正确性和文献证据质量须人工核对；来源数量不代表科学结论验收。
- 教育科研按用户选择共享任务与成果，不提供该服务器内的客户级数据隔离。
- 完整九类真实生物学长流程未在本轮重跑；原有任务恢复与删除逻辑通过回归测试，不能代替真实数据和长时断网验收。
- 发布构建、安装包校验和实际桌面替换状态以 release-verification.json/installation-verification.json 为准；无该记录时不得视为已安装。
