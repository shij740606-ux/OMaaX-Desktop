| 优先级 | 功能 | 发现 | 本轮处理 |
| --- | --- | --- | --- |
| 高 | 长流程用量与重试保护 | Windows 临时文件替换偶发 EPERM，真实回归再次复现；会打断保护状态保存 | 对 EPERM/EACCES/EBUSY 最多重试 5 次，累计等待 775ms；持续失败仍抛错。始终保留旧文件，不采用删除目标再覆盖的做法；无状态变化的轮询不重复写盘 |
| 高 | 知识库异常响应 | 列表、答案、历史或引用字段不是预期类型时可能触发 React 渲染错误 | 在更新页面状态前校验响应。异常返回可理解的错误，保留已有页面和问题，允许重试 |
| 高 | 问答保存失败 | 仅显示提示，继续操作会清除提示或丢失尚未保存的回答 | 增加重试保存、显式放弃保存及确认；保存未完成时阻止新问题和切换会话。重试保存不重复请求模型 |
| 中 | 保存响应丢失 | 服务端可能已经保存，但客户端看到失败；直接重试会重复写入 | 重试前读取最新历史，核对最后一条回答及引用，已保存则不重复写入。这不是服务端事务幂等保证，其他设备同时修改同一会话仍需进一步测试 |
| 中 | 连续刷新列表 | 迟到的旧列表可能覆盖较新的列表 | 按请求顺序忽略过期响应 |
| 高，服务端 | 管理员账号 | 上轮真实测试确认文档中的默认管理员凭据仍有效 | 需要服务管理员更换。本轮未修改生产管理员密码，未在源码或报告中记录密码 |

## 仍需要更多真实场景验证

1. **数小时到数天任务**：真实监督进程崩溃、主机重启、磁盘接近满、断网后的恢复，以及已完成生物学结果是否正确。当前通过的是机制测试，不等于完整九类流程科学验收。
2. **多人持续并发**：多个客户端同时更新同一知识库会话或共享科研任务；服务端是否提供版本冲突和幂等保护。默认管理员凭据应先处理，再安排对外负载测试。
3. **知识库热更新**：长响应超时、服务重启、字段变化和引用质量需持续观察。本轮加强了错误恢复，没有加大真实问答压力。
4. **未保存数据的进程崩溃**：保存失败的回答暂存在当前页面内存中，退出账号、关闭软件或系统崩溃仍可能丢失；界面明确提示先重试或复制。没有把账号内容写入不隔离的浏览器持久存储。
5. **科研生成任务**：复杂 PDF、多文件 LaTeX、长 PPTX、并发编辑及生成中服务重启，需专门的代表性资料和更长运行窗口。已有代理、保存/删除及超时回归不能代替每种真实生成结果的人工检查。
